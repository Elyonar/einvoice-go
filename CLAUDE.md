# CLAUDE.md — Project Instructions for einvoice-go

This file provides context for Claude Code and any AI agent working on this project.

## Project Overview

Go SDK for the Yona e-invoicing API, the port of `@useyona/einvoice-js` (`Elyonar/einvoice-js`,
locally `../elyonar-sdk`) module for module. It covers **exactly what an API key may call** (owner
ruling R77): invoicing, submissions to the tax authority, output and share links, items, reference
data, buyers, the read-only seller, received invoices and issued history, invoice settings, the tax
connection, the organisation (read), billing reads and webhooks (read, test, redeliver). Users,
invitations, roles, API keys, organisation management, collections, purchases and webhook-endpoint
writes are user-only and are not in the SDK.

Go 1.22+. Zero dependencies outside the standard library (`net/http`, `encoding/json`, `crypto/*`).
Module `github.com/elyonar/einvoice-go` (lower-case, permanent), package `einvoice`, one flat package.
The ports are versioned independently of einvoice-js (`version.go`); the einvoice-js commit (or tag)
pinned in `scripts/sync.sh` records which JS release this one tracks.

## Source of truth

- **einvoice-js is the source of truth for every Yona SDK.** `make sync` fetches it at the commit
  (or tag) pinned in `scripts/sync.sh` (`EINVOICE_JS_REF`) and copies three things:
  `scripts/openapi-api-key-ops.json` (the API-key operations of the gateway's OpenAPI),
  `tests/vectors/webhook-signature.json` (the backend-signed webhook test vectors) and the generated
  models `types_gen.go` (rendered by einvoice-js's `scripts/gen-types.mjs --lang go`). Never edit
  those three by hand. `make sync-check` (CI) fails when any differs from the pinned commit. Bumping
  the pin is how this SDK takes a new API surface. `EINVOICE_JS_DIR=../elyonar-sdk make sync` uses a
  local checkout (development).
- **Parity is enforced** by `parity_test.go`: every SDK method must call exactly one snapshot
  operation; every snapshot operation must have a method or an entry (with a reason) in
  `excluded_operations.go`; `Idempotency-Key`s are generated exactly on the POST/GET routes that
  accept one; 99 methods in 23 modules. Go cannot synthesise arguments by reflection, so the test
  keeps a registry (`parityMethods`) of one call per method and a reflection pass that fails when an
  exported service method is not registered.
- The transport contract, the error hierarchy, the webhook verification and the method names (in
  `PascalCase`, Go initialisms: `DownloadPDF`, `LookupTaxID`) mirror einvoice-js `src/`; when in
  doubt, read the TypeScript and its tests.

## Key rules

- **Host.** `DefaultBaseURL = "https://gp.useyona.com"` serves sandbox and live. The name is
  permanent; infrastructure moves by DNS, never by changing it. Never switch hosts by mode: the key
  prefix (`sk_test_` / `sk_live_`) is the mode. `WithBaseURL` is an advanced override only. The SDK
  never reads the environment; `scripts/run_examples` repoints the examples with
  `-ldflags "-X github.com/elyonar/einvoice-go.defaultBaseURLOverride=…"`.
- **Errors** come from the envelope: `meta.errorCode`, `meta.message`, `meta.errors`
  (single-key objects), `meta.requestId` (fallback `x-request-id`). Every refusal is a typed wrapper
  (`*ValidationError` …) that unwraps to `*APIError`; use `errors.As`, never type switches on `err`.
- **Retries** only for GET/PUT/DELETE and requests carrying an `Idempotency-Key`. A service passes
  `Idempotent: true` only for routes whose backend reads `Idempotency-Key`; PATCH routes send it
  only when the caller gives `WithIdempotencyKey`. A cancelled `context.Context` is never retried
  and is returned as `ctx.Err()`.
- **Timeouts and delays are `time.Duration`**; einvoice-js uses milliseconds. One deadline per
  attempt covers the headers and the body.
- **Webhooks**: HMAC-SHA256 over `t + "." + raw body`, header `Yona-Signature: t=…,v1=…[,v1=…]`,
  ±300 s. The vectors in `tests/vectors/` come from the backend signer, via einvoice-js.
- **Models are structs with wire names in their json tags**; optional and nullable fields are
  pointers (`einvoice.Ptr(v)` makes one). Enums are closed `string` types with constants; the API
  may add values, so never fail on an unknown one. `Amount` keeps a `string | number` as sent.
- **Generics**: `Page[T]`, `Paginated[D]`, `Paginate[T]`, `Collect[T]`; no `iter` (Go 1.22).

## Guides (examples/ → guides/guides.json)

- Each `examples/<id>/main.go` is one recipe: header `// @recipe <id> <Title>` + `// @summary <text>`,
  then steps `// @step <id> <Title>`, optionally followed directly by `// @text …`, `// @op
  <operationId>` and `// @quickstart`. A step's code runs until the next `@step`; everything before
  the first step (package, imports, `func main() {`, its setup) is hoisted into it, and the quick
  start gets it with unused imports pruned and the braces it leaves open closed. Recipe and step ids
  are the same in every SDK so the portal can tab between languages.
- Examples import `github.com/elyonar/einvoice-go`, pass only `os.Getenv("YONA_API_KEY")` to
  `einvoice.New`, and must exit non-zero (`log.Fatal`) when what they show does not hold.
- After changing an example: `make lint`, `go vet ./examples/...`, `make guides`, commit
  `guides/guides.json` (`guides_test.go` fails when it is stale), and run it live (`make examples`).

## Adding or changing a method

1. Bump `EINVOICE_JS_REF` in `scripts/sync.sh` to the einvoice-js commit (or tag) that has the change,
   `make sync`, read the diff of the snapshot and of `types_gen.go`.
2. Add the method to the module of its API tag, typed with the generated `<Op>Query` / `<Op>Body`
   / `<Op>Data` / `<Op>Item`, named as einvoice-js names it (in `PascalCase`); or add the operation
   to `excluded_operations.go` with a reason. Add it to `parityMethods` in `parity_test.go`.
3. A doc comment on every public method (what it does, the capability it needs, charging, idempotency).
4. `make test` (the parity test fails until both directions agree), `make lint`.
5. Update README (API reference) and CHANGELOG.

## Conventions

- Conventional commits: `type(scope): subject`. Scopes: client, invoices, submissions, output, items,
  reference, inbound, sellers, buyers, billing, webhooks, organization, parity, smoke, types, config,
  deps, release. **Never add Claude or any AI assistant as co-author.**
- `gofmt` and `go vet` over everything (`make lint`; golangci-lint runs when installed). Tests use a
  fake `Transport` (`helpers_test.go`), never the network.
- Coverage threshold 80 % (`go test ./... -cover`).
- Releasing: bump `Version` in `version.go`, update CHANGELOG, `make guides`, merge to `main`; CI tags
  `v<version>` (PUBLISHING.md). Stay on `v0.x`.
