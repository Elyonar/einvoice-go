# Contributing to einvoice-go

## Development setup

```bash
git clone https://github.com/Elyonar/einvoice-go.git
cd einvoice-go
make test
make lint
```

Go 1.22 or newer; no dependencies outside the standard library. `make sync` needs git and Node 22:
the models, the API snapshot and the webhook test vectors are generated by
[einvoice-js](https://github.com/Elyonar/einvoice-js), the source of truth for every Yona SDK, at
the einvoice-js commit (or tag) pinned in `scripts/sync.sh`. Never edit `types_gen.go`,
`scripts/openapi-api-key-ops.json` or `tests/vectors/webhook-signature.json` by hand.

## Commit convention

[Conventional Commits](https://www.conventionalcommits.org/): `<type>(<scope>): <subject>`.

Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
Scopes: `client`, `invoices`, `submissions`, `output`, `items`, `reference`, `inbound`, `sellers`,
`buyers`, `billing`, `webhooks`, `organization`, `parity`, `smoke`, `types`, `config`, `deps`, `release`.

## Pull requests

- `make lint` and `make test` must pass (CI runs them on Go 1.22, 1.23 and stable, plus
  `make sync-check` and `make guides-check`).
- A new or changed method keeps parity with the snapshot (`parity_test.go`: add it to
  `parityMethods` too, the reflection pass fails otherwise) and is named as einvoice-js names it, in
  Go's `PascalCase` with Go initialisms (`DownloadPDF`, `LookupTaxID`).
- Update the README's API reference and the CHANGELOG.
